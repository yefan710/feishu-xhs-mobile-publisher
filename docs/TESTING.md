# 验收清单

四层验收分开记录，任何一层未做就不能报告全链路通过。

## A. 自动测试

```sh
npm ci
npm test
npm audit
```

覆盖：字段契约/映射、账号与JW同号不同record、18张顺序与Unicode、HTTPS拒绝、过期拒绝、旧素材快照拒写、精确状态幂等写和回读、权限拦截、账号撤销、私有目录不可访问、登录限流、Android原生anchor手势、老浏览器超时兼容。全部使用合成记录与临时目录，无真实飞书状态写入。

这些测试证明构造/服务器行为，不证明小红书接受协议。CI只运行这层。

## B. 实际浏览器点击

`npm run demo` → `http://127.0.0.1:3000/`，demo / demo-only-password：

1. 登录；默认否列表有两条同JW不同账号。
2. 选演示账号A和JW10001；只保留正确record。
3. 点记录；三张占位PNG都加载，序号连续，正文/标签显示。
4. 展开状态纠正，标是；页面回读确认，否列表移除该条。
5. 恢复否；该条重新出现。
6. 切账号B，其状态仍否；切是/全部筛选结果正确。
7. 电脑点发布应明确说明需对应手机，不能回写/打开App。
8. 退出登录后无法读素材；保存合成数据截图与步骤。

可用Chrome/CDP优先；如果工具不可用，记录原因并用可操作浏览器补验。必须真实点击，不能仅检查DOM文本、API或构建产物。

## C. 真实飞书测试记录

由部署者新建/指定测试行，记录record_id，账号和JW不同于重要历史业务。检查字段读权限、完整图文prepare、所有图片URL的公网可达性和实际下载、测试状态是→否回读；只改这一条。任意缺失明确报告为未验证。

在另一个未登录浏览器中验证限时图片能直接返回图片，不转到登录页；过期后410。改变测试素材文字再用旧任务回写，应409并不改状态；重新prepare后才允许继续。

## D. 手机 App 交接

| 测试信息 | 必须记录 |
|---|---|
| 设备 | 品牌/型号、Android或iOS版本 |
| 浏览器 | 名称和版本，外部浏览器或内嵌 |
| App | 小红书版本和当前登录账号（可脱敏） |
| 路线 | 自动/Intent/scheme/iOS |
| 导入 | 图片数量和顺序；标题、正文、换行、标签分别通过/失败 |
| 回写 | 指定测试record的是否发布、前后值、回读证据 |
| 发布 | 是否由人点最终发布；未发布则写未发布 |

Android先测试Chrome外部浏览器Intent；不成功时恢复否，再手动scheme测试。iOS用Safari。不要自动安装Lumi/APK，不绕过浏览器警告。不能用UA伪装的桌面测试代替真机。

如果App没有打开，先恢复否，记录点击表现和版本；若App打开但只导入部分字段，也判交接未通过。最终App发布与飞书点击状态是两个不同结果。

## 部署与回滚

检查HTTPS有效、移动网络可达、重启数据卷保留、旧站功能正常、非授权客户端403、私有文件404。回滚代码前保留`.env`/data配置；不要批量改历史状态作为回滚。Docker生产部署和真实飞书/手机验收必须在朋友环境再次执行。
